# OPS-0001: Git履歴修正 + UTF-8設定 + コミット分割

- 日時: 2026-02-24
- 種別: 運用作業（Git履歴のリライト）

---

## 背景

v1.0.1 のリファクタリング（実行ステータス正確化・設定永続化分離等）が、以下の問題を含む状態で push されていた。

1. **コミットメッセージの文字化け**  
   PowerShell のデフォルトエンコーディングが Shift_JIS のため、`git commit -m` で渡した日本語の本文が壊れていた  
   - `45cda9e`: タイトルは正常だが本文が Shift_JIS→UTF-8 の文字化け（`繧ｹ繧ｭ繝｣繝ｳ...`）
   - `794ebf8`: 孤立コミット（amend前の残骸）。日本語が全て `?????` に化けていた

2. **不要なマージコミット**  
   `d3f6cca` はローカルとリモートの同一内容コミットのマージ（不要）

3. **変更の混在**  
   3カテゴリの変更（設定永続化・実行ステータス・ViewModel統合）が 1 コミットに混在していた

4. **ビルド成果物の混入**  
   `*_wpftmp.csproj` や `アプリケーション/*.dll` 等がコミットに含まれていた

---

## 作業内容

### Phase 1: Git UTF-8 設定（今後の文字化け防止）

```powershell
# Git のコミットエンコーディングを UTF-8 に設定
git config --global i18n.commitEncoding utf-8

# Git のログ出力エンコーディングを UTF-8 に設定
git config --global i18n.logOutputEncoding utf-8

# 日本語ファイル名のエスケープを無効化（\xxx 表示の防止）
git config --global core.quotePath false
```

**理由**: Windows の PowerShell はデフォルトで Shift_JIS（CP932）を使う。Git がコミットメッセージを書き込む際にエンコーディングの不整合が起きるため、明示的に UTF-8 を指定する。

### Phase 2: PowerShell プロファイルに UTF-8 設定追加

```powershell
# プロファイルパスの確認
$PROFILE
# → C:\Users\Rakua\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1

# プロファイル作成（存在しなかった）
New-Item -Path $PROFILE -ItemType File -Force

# UTF-8 設定を書き込み
Set-Content -Path $PROFILE -Value @"
# UTF-8 encoding for Git and console
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding  = [System.Text.Encoding]::UTF8
`$env:LANG = "ja_JP.UTF-8"
"@ -Encoding UTF8
```

**理由**: PowerShell 新規セッションのたびに UTF-8 設定が適用されるようにする。これにより `git commit -m` で日本語を渡しても文字化けしない。

### Phase 3: コミット履歴のリセット

```powershell
# 現在のセッションで UTF-8 を有効化（プロファイルはまだ読み込まれていないため）
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding  = [System.Text.Encoding]::UTF8

# 変更前のコミットグラフ確認
git log --oneline 715f421..HEAD
# d3f6cca Merge branch 'main' of ...    ← 不要なマージ
# 45cda9e v1.0.1にアップデート           ← 本文文字化け、変更混在
# f30e184 Refactor execution progress... ← 同一tree（リモート版）

# v1.0.1 直前のコミット（715f421）まで soft reset
# --soft: コミットだけ巻き戻し、変更は全てステージングに残る
git reset --soft 715f421

# ステージングから全て外してワーキングツリーに戻す
git reset HEAD
```

**理由**: `--soft` で変更内容を失わずにコミットだけ消す。その後 `git reset HEAD` でアンステージし、ファイル単位で選択的にコミットできる状態にする。

### Phase 4: カテゴリ別に分割コミット

#### Commit 1: .gitignore 更新

```powershell
# .gitignore にビルド成果物・一時ファイルの除外ルールを追記
# （エディタで アプリケーション/ と *_wpftmp.csproj を追加）

git add .gitignore
git commit -m "chore: .gitignore更新（ビルド成果物・一時ファイル除外）" \
           -m "アプリケーション/ と *_wpftmp.csproj を .gitignore に追加"
```

**理由**: .gitignore を先にコミットすることで、以降のコミットにビルド成果物が混入しなくなる。`git status` にも表示されなくなるため作業が明確になる。

#### Commit 2: 設定永続化基盤

```powershell
git add ModLangOrganizer/Models/AppSettings.cs \
        ModLangOrganizer/Infrastructure/SettingsStore.cs \
        ModLangOrganizer/Infrastructure/SettingsService.cs

git commit -m "feat: 設定永続化基盤（AppSettings/SettingsStore/SettingsService）" \
           -m "設定処理をSettingsServiceに分離し、デバウンス＋直列化で安全に保存。" \
           -m "SettingsStoreでアトミック保存（.tmp→Replace/Move）、破損JSON読込時はsettings.broken.*.jsonに退避し既定値復帰。"
```

**理由**: 設定永続化は他の変更から独立したインフラ層の追加。先にコミットすることで、後続の ViewModel コミットがこれに依存する形になり、依存方向が明確。

#### Commit 3: 実行ステータスの正確化

```powershell
git add ModLangOrganizer/Models/ExecutionProgress.cs \
        ModLangOrganizer/Domain/Executor.cs

git commit -m "feat: 実行ステータスの正確化（ExecutionProgress/Executor）" \
           -m "実行ステータス更新をExecutor側の進捗モデルに分離。" \
           -m "Started/Completed + FinalStatus を返すよう変更し、Skip/Warning/FailがUIに正しく反映される。"
```

**理由**: ExecutionProgress モデルと Executor の変更はドメイン層で完結している。ViewModel 側の対応とは分離してコミットすることで、変更の目的が明確。

#### Commit 4: ViewModel 統合

```powershell
git add ModLangOrganizer/ViewModels/MainViewModel.cs \
        ModLangOrganizer/MainWindow.xaml.cs

git commit -m "feat: ViewModel統合（ステータス・パス検証・設定連携）" \
           -m "MainViewModelにIDisposable実装、設定のLoad/Save連携、コマンド有効条件の分離。" \
           -m "ScanCommandの有効条件をDirectory.Exists連動にし、無効パスで明示メッセージを表示。" \
           -m "起動時に保存済みTargetDirが存在しない場合は空に戻して警告表示。" \
           -m "アプリ終了時にMainViewModel.Dispose()で設定フラッシュ。"
```

**理由**: MainViewModel.cs には 3 カテゴリの変更が密に絡んでいるため（プロパティ setter に SaveSettings + RefreshCommands の両方が入る等）、ファイル単位での分割が安全。ハンク単位で分けるとコンパイル不可になるリスクがあった。

#### Commit 5 & 6: ドキュメント

```powershell
git add 設計書.md
git commit -m "docs: 設計書更新（v1.0.1実装反映）"

# 進捗.md にタスク記録を追記してからコミット
git add 進捗.md
git commit -m "docs: 進捗.md更新（v1.0.1リファクタリング記録）"
```

**理由**: コード変更とドキュメント変更を分離。1 コミット = 1 目的の原則に従う。

### Phase 5: Force Push

```powershell
# --force-with-lease: リモートが想定通りの状態かチェックしてから強制上書き
# （他の人が push していたら拒否される安全策）
git push --force-with-lease origin main
```

**理由**: 履歴を書き換えたため通常の push は拒否される。`--force` ではなく `--force-with-lease` を使うことで、他者の push を上書きするリスクを回避。

### 適用された永続設定
| 設定 | コマンド | 効果 |
|------|---------|------|
| `i18n.commitEncoding` | `git config --global` | コミットメッセージを UTF-8 で保存 |
| `i18n.logOutputEncoding` | `git config --global` | `git log` 出力を UTF-8 で表示 |
| `core.quotePath` | `git config --global` | 日本語ファイル名をそのまま表示 |
| PowerShell Profile | `$PROFILE` に記述 | 新規セッションで自動的に UTF-8 適用 |
