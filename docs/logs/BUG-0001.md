- ID: BUG-0001
- 日付: 2026-02-23
- タイトル: スキャン実行時に Logs 更新でクラッシュ（クロススレッド更新）

## 現象
スキャン実行中、画面が突然終了する（クラッシュ）。

## 期待結果 / 実結果
- 期待結果: スキャン中でもログが正常表示され、処理が継続する。
- 実結果: ログ追加タイミングでアプリが終了する。

## 発生条件
- `Task.Run` で動くスキャン処理中に `_logger.Info/_logger.Error` を呼ぶ。
- `LogEntries` が WPF `ListBox` に `ItemsSource` バインドされている状態。

## 再現手順（最小）
1. アプリを起動する。
2. jar を複数含むフォルダを選択する。
3. 「スキャン」を実行する。
4. ログが増えるタイミングでクラッシュが発生することがある。

## ログ / スタックトレース
- 実機クラッシュログ: 未取得（本環境では GUI 実行ログの採取不可）。
- コード上の再現経路から、WPF の `CollectionView` クロススレッド更新例外が原因と判断。
- 想定例外メッセージ:
  - `This type of CollectionView does not support changes to its SourceCollection from a thread different from the Dispatcher thread.`

## 原因
`Logger` が `ObservableCollection<LogEntry>` に対して、UI スレッド外から `Entries.Add` / `Entries.Clear` を実行していた。

## 対策（修正内容）
- `Logger` に `Application.Current?.Dispatcher` を保持。
- `Add`:
  - UI スレッド外なら `Dispatcher.BeginInvoke` で `Entries.Add` を UI スレッドへ移送。
- `Clear`:
  - UI スレッド外なら `Dispatcher.Invoke` で `Entries.Clear` を UI スレッドへ移送。

## 検証（直った根拠）
- ユーザー環境で再スキャン後、「無事動きました」と確認済み。
- 修正後、ログ追記時のクラッシュ再発報告なし。

## 再発防止（テスト/ガード/監視/運用）
- 運用:
  - `ObservableCollection` は UI スレッド以外で直接更新しないルールを徹底。
- ガード:
  - ログ更新のスレッド制御を `Logger` に集約し、呼び出し側での分散実装を禁止。
- 追加検討:
  - `App.xaml.cs` に `DispatcherUnhandledException` / `TaskScheduler.UnobservedTaskException` の記録を追加。
