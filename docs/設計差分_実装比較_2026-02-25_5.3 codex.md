# 設計差分メモ（設計書v1.3 vs 現行実装）

作成日: 2026-02-25  
対象実装: `ModLangOrganizer`（`CHANGELOG v2.1.2` 時点）

## 1. 主要差分（今回の設計書更新で反映した内容）

1. 出力先構造の変更
- 旧設計: `<OutputRoot>/<modid>/lang/...`
- 現行実装:
  - lang候補1件: `<OutputRoot>/<jar名>/...`
  - lang候補複数: `<OutputRoot>/<jar名>/<modid>/...`
- 補足: `lang` フォルダ自体は作らず、lang配下ファイルを直接出力する。

2. jar単位での集約ルール
- 旧設計は modid 集約中心だったが、現行は `jar` 単位の出力構成が基準。
- 複数候補時のみ `<modid>` で枝分かれする。

3. langフォールバック機能の追加
- `LangFallbackEnabled`, `LangFallbackSourceName`, `LangFallbackTargetName` を実装。
- ターゲット名ファイルが無い場合だけ、ソース名ファイルからコピー生成。
- 拡張子は保持される（例: `en_us.json` -> `ja_jp.json`）。

4. 設定永続化仕様の具体化
- `%LocalAppData%/ModLangOrganizer/settings.json` へ保存。
- デバウンス保存、直列化、アトミック書込（`.tmp -> Replace/Move`）。
- 破損JSON検出時は `settings.broken.<timestamp>.json` へ退避。

5. 実行計画の責務変更
- 旧設計案: `OperationPlanner` クラスで計画生成。
- 現行実装: `JarScanner` がスキャン結果と planned operations を生成。

6. UIオプションの拡張
- `OutputRoot` の手動変更と「親フォルダと同じ場所に出力」トグルを実装。
- langフォールバック設定UI（有効/無効 + source/target名）を実装。

## 2. 実装と旧設計のギャップで、特に見落としやすい点

1. スキャンの予定操作に `FallbackCopy` は出ない
- 実装ではフォールバックは実行時のみ判定される。
- そのためスキャン件数（E/D/C/CF/CL/S）と実行ログで見える操作が完全一致しない場合がある。

2. `FileSystemWatcher` は実質常時有効
- 旧設計の「任意で watcher」は、現状UIからON/OFFできない。
- `TargetDir` が有効なら監視開始される実装。

3. スナップショット鮮度表示はグローバル通知中心
- 実装は `SnapshotFresh`（全体フラグ）で再スキャン警告を出す。
- テーブル各行の `SnapshotState` を個別更新する処理は現在は持っていない。

## 3. この差分メモの使い方（運用提案）

1. 仕様変更のたびに、本ファイルへ「旧設計との差分」を先に追記する。
2. 差分が固まった時点で `設計書.md` 本文へ昇格反映する。
3. テスト観点は差分単位で追加し、実装と文書のズレを継続的に縮める。
