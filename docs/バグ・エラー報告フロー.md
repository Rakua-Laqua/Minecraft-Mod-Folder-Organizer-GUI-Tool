# バグ・エラー報告フロー

## 1. 目的
- 再発防止に必要な情報を、同じ形式で記録・参照できる状態にする。

## 2. 基本ルール
- `進捗.md` の「バグ / エラー修正ログ」に必ず追記する。
- 重大・複雑な不具合は `docs/logs/BUG-xxxx.md` または `docs/logs/ERR-xxxx.md` を作成する。
- `進捗.md` 側には必ず詳細ログへの索引（ファイル名）を残す。

## 3. 手順
1. 不具合の現象・再現条件・原因・対策を整理する。
2. `進捗.md` の「バグ / エラー修正ログ」に要約を追記する。
3. 重大・複雑な場合は `docs/logs` に詳細ログを作成する。
4. 変更後、関連ファイルのパスを相互に参照できるようにする。

## 4. ID 採番
- 形式: `BUG-0001` / `ERR-0001` のゼロ埋め4桁。
- 新規作成時は既存最大番号 + 1 を採番する。

## 5. テンプレート（docs/logs/BUG-xxxx.md / ERR-xxxx.md）
```md
- ID: BUG-XXXX or ERR-XXXX
- 日付: YYYY-MM-DD
- タイトル:

## 現象
## 期待結果 / 実結果
## 発生条件
## 再現手順（最小）
## ログ / スタックトレース
## 原因
## 対策（修正内容）
## 検証（直った根拠）
## 再発防止（テスト/ガード/監視/運用）
## 関連リンク（該当ファイル/コミット/Issue）
```
